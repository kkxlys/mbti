# 前端整体设计方案

项目暂定名：`星轨志愿局`

定位：给高考毕业生使用的娱乐化人格测试 + AI专业推荐工具。视觉要二次元、沙雕、年轻，但核心信息必须可信、清楚、适合付费转化。

## 设计主张

整体风格选择：`赛博校园轻视觉小说 + 抽卡式报告 + 志愿填报工具`

页面不做传统营销落地页，第一屏就是可操作的成绩输入和测试入口。视觉上用二次元校园、未来终端、角色面板、抽卡揭晓这些语言，但组件保持工具产品的清晰度。

关键词：

- 明亮赛博校园
- 高考后精神状态
- 抽象但有用
- 角色属性面板
- 报告抽卡解锁
- 专业推荐雷达

避免：

- 满屏紫蓝渐变
- 黑底霓虹到看不清字
- 纯表情包式廉价搞笑
- 过度营销式大Hero
- 卡片套卡片
- 把“MBTI官方”作为卖点

## 目标用户

核心用户是刚高考结束的学生，使用场景多在手机端。次级用户是家长，可能会看报告页，所以结果页要比答题页更稳重一点。

设计需要兼顾两种心理：

- 学生：希望好玩、轻松、有梗、愿意分享。
- 家长：希望报告看起来不是胡闹，专业建议有依据。

因此答题流程可以更抽象，报告页要更结构化。

## 页面流程

### 1. 首页 / 成绩输入

路径建议：`/`

首屏直接展示产品核心功能：

- 左侧或顶部：品牌名 `星轨志愿局`
- 主标题：`测一测你的高考后人格航线`
- 主体：成绩输入面板
- 附加：省份、选科、位次、目标城市、兴趣标签
- CTA：`开始人格校准`

桌面端可以使用双栏布局：

- 主栏：成绩表单
- 辅栏：二次元校园角色插画 + 当前“属性条”预览

移动端只保留单栏，插画变成顶部横幅或背景局部，不压缩表单空间。

### 2. 测试开场

路径建议：`/quiz/intro`

用轻视觉小说方式开场，但不要过长：

- 一句剧情：`高考副本已通关，志愿系统正在读取你的隐藏人格参数。`
- 展示题量：48题
- 预计时长：5-7分钟
- 提醒：没有标准答案，按第一反应选

CTA：`进入测试`

### 3. 答题页

路径建议：`/quiz`

答题页是核心体验，必须快、稳、低负担。

布局：

- 顶部：进度条 `12 / 48`，右侧可显示保存状态
- 中部：题目文案
- 下方：4个选项按钮
- 底部：上一题、下一题或自动下一题

交互：

- 选择后 180ms 高亮，再自动进入下一题，也允许用户在设置中关闭自动下一题。
- 选项点击区域至少 44px 高。
- 选项文案允许换行，不截断。
- 保留返回上一题修改答案。
- 每8题出现一次轻反馈，例如 `脑洞跃迁指数正在上升`。

视觉：

- 题目区域像“系统任务窗口”
- 选项像“对话选择项”
- 进度条像“能量槽”
- 不使用浮夸转场，防止移动端卡顿

### 4. 报告预览 / 支付墙

路径建议：`/checkout`

答完题后先展示部分结果，但不展示完整人格和专业建议。

可展示：

- 成绩已读取
- 48题人格参数已计算
- 维度雷达图打码或模糊
- 专业推荐数量，例如 `已匹配 12 个高相关专业`
- 支付后解锁：完整人格、专业Top榜、避坑提醒、志愿策略

支付区：

- 微信支付
- 支付宝
- 订单金额
- 支付状态

注意：

- 不要假装AI已经完成完整报告；正确状态是“支付后生成完整AI报告”。
- 支付按钮要稳定、清楚、可信，不要过度沙雕。

### 5. 报告生成中

路径建议：`/report/generating`

支付成功后进入异步生成页。

状态文案示例：

- `人格参数校准中`
- `正在读取你的学科属性`
- `正在匹配专业宇宙坐标`
- `正在生成志愿建议`

交互：

- 页面轮询报告状态，或用 SSE/WebSocket。
- 超过30秒展示“稍后查看”入口。
- 失败时提供重试和联系客服，不要卡死。

### 6. 完整报告页

路径建议：`/report/:id`

报告页比答题页更专业，形成付费后的价值感。

结构：

1. 人格类型卡
   - 类型代码，例如 `ENFP`
   - 沙雕称号，例如 `志愿宇宙冒险家`
   - 一句话解释

2. 四维度雷达 / 条形图
   - E/I、S/N、T/F、J/P百分比
   - 每个维度给短解释

3. 学科属性分析
   - 各科成绩条
   - 优势学科
   - 可能适配能力

4. 专业推荐Top榜
   - 专业名称
   - 匹配度
   - 推荐理由
   - 学习内容
   - 未来方向
   - 风险提醒

5. 谨慎选择专业
   - 不直接否定，只写“需要额外确认”
   - 给原因和补救建议

6. 志愿行动清单
   - 查分数线
   - 看培养方案
   - 对比城市
   - 和家长沟通

7. 分享海报
   - 生成图片
   - 保存或分享

### 7. 分享页

路径建议：`/share/:id`

分享页只展示轻量内容：

- 人格称号
- 维度概览
- 一句沙雕短评
- 入口按钮：`我也测测`

不要暴露完整专业建议，保留付费价值。

## 视觉系统

### 色彩

采用浅色为主，霓虹点缀。这样既有二次元气质，又不影响可读性。

```css
:root {
  --bg: #f7f8ff;
  --surface: #ffffff;
  --surface-soft: #eefbff;
  --ink: #171625;
  --muted: #64627a;
  --border: #e6e8f5;

  --primary: #ff4f81;
  --primary-strong: #e3366a;
  --secondary: #00b8c8;
  --accent: #ffd84a;
  --mint: #45d6a3;
  --violet-accent: #7c5cff;

  --success: #28b778;
  --warning: #ff9b3d;
  --danger: #e84b5f;
}
```

使用比例：

- 背景和内容面：70%
- 文字和线框：15%
- 主色粉红：8%
- 青色、黄色、薄荷绿、紫色点缀：7%

不要让紫色或蓝色成为绝对主色，避免页面变成常见AI渐变模板。

### 字体

推荐：

- 中文正文：`Noto Sans SC`
- 英文和数字：`Inter`
- Logo或少量大标题：可使用自定义字形或生成位图标题

字号：

- 移动端正文：16px
- 选项文字：16px
- 表单标签：14px
- 页面标题：28-36px
- 报告页模块标题：20-24px

不使用随视口变化的字号。移动端长词和长句必须换行，不允许挤出容器。

### 圆角和边框

- 卡片：8px
- 按钮：8px
- 输入框：8px
- 标签：6px
- 大插画容器：8px

避免过度圆润的胶囊按钮。二次元感主要靠插画、色彩、动效和文案，而不是把所有组件做成气泡。

### 插画与资产

建议准备3类视觉资产：

- 主视觉：明亮赛博校园 + 志愿终端 + 学生角色
- 小图标：学科、人格维度、专业门类
- 报告徽章：16种人格称号徽章

资产格式：

- 主视觉：WebP / AVIF
- 徽章：SVG或WebP
- 分享海报：服务端或前端Canvas生成PNG

可以有看板角色，但不要首屏阻塞加载。Live2D如果要做，必须延迟加载，并提供关闭入口。

## 组件规范

### 顶部导航

移动端：

- 左侧品牌名
- 右侧订单/报告入口
- 高度 56px

桌面端：

- 品牌
- 测试入口
- 报告查询
- 帮助

导航不要压过主流程。

### 成绩输入组件

字段：

- 省份
- 科类 / 选科组合
- 总分
- 语文、数学、外语
- 选考科目分数
- 位次，可选但强推荐

交互：

- 输入后即时生成“学科属性条”
- 错误提示显示在字段下方
- 数字键盘适配移动端
- 不用 placeholder 代替 label

### 答题选项

选项是整块可点击区域：

- 默认：白色面 + 细边框
- 悬停：边框变主色
- 选中：主色描边 + 浅粉背景 + 左侧小标记
- 禁用：透明度降低

不要用颜色作为唯一状态，选中状态同时要有图标或文字标识。

### 进度条

形式：

- 顶部细能量槽
- 显示当前题号
- 每12题一个阶段节点，对应一个维度区间，但不要向用户暴露具体维度，避免刻意作答

### 支付组件

支付页要收敛，减少玩梗：

- 订单金额清晰
- 支付方式清晰
- 支付安全提示
- 支付中状态
- 支付失败重试

按钮文案：

- `解锁完整报告`
- `继续支付`
- `我已完成支付`

### 报告卡片

报告卡片要专业，不要像营销海报堆满贴纸。

推荐卡结构：

- 专业名
- 匹配度
- 推荐理由
- 学什么
- 未来可能方向
- 需要确认的风险

同一层级不做卡片套卡片。内部信息用分割线、标签、短段落组织。

## 动效规范

整体动效应服务流程，不做纯装饰。

- 页面进入：180-260ms，轻微上移 + 淡入
- 选项选中：120-180ms，边框和背景变化
- 题目切换：220ms 横向滑动或淡入
- 支付成功：短确认动画，不超过800ms
- 报告生成：分阶段进度动画

必须支持 `prefers-reduced-motion`，开启后只保留淡入或直接切换。

不要动画：

- 宽高变化
- 大面积背景闪烁
- 持续旋转的大元素
- 干扰阅读的漂浮物

## 响应式规则

移动端优先：

- 375px宽度必须完整可用
- 主CTA固定在底部时，要给内容留安全距离
- 表单一列
- 答题选项一列
- 报告推荐卡一列

平板：

- 表单可两列
- 报告图表和解释可左右分栏

桌面：

- 最大内容宽度 1120-1200px
- 成绩页双栏
- 报告页可使用左侧目录 + 右侧内容

不要出现横向滚动。长专业名和长选项必须换行。

## 可访问性

- 正文对比度至少 4.5:1
- 所有输入有可见 label
- 所有图标按钮有 `aria-label`
- 键盘可完成答题和支付前流程
- 错误信息靠近字段
- 支付状态用文字说明，不只靠颜色
- 图表提供文字摘要

## 性能策略

首屏：

- 题库JSON可静态加载或随页面预取
- 主视觉图片压缩为WebP/AVIF
- 非关键插画延迟加载
- 字体使用 `font-display: swap`

答题：

- 48题一次加载到内存
- 答案存 localStorage + 服务端草稿
- 页面切换不重新请求题库

报告：

- 图表组件动态加载
- 分享海报生成按需触发
- AI生成状态轮询间隔逐步放大

## 推荐技术实现

前端栈：

- Next.js
- TypeScript
- Tailwind CSS
- shadcn/ui 作为基础组件
- Framer Motion 做关键转场
- ECharts 做报告图表
- Zustand 保存答题临时状态

目录建议：

```text
src/
  app/
    page.tsx
    quiz/
    checkout/
    report/
  components/
    score/
    quiz/
    payment/
    report/

    question-bank.ts
```

## 文案语气

答题页可以抽象：

- `志愿系统正在读取你的隐藏参数`
- `你的脑洞跃迁值出现波动`
- `当前人格信号稳定，继续校准`

支付页要克制：

- `支付后生成完整AI报告`
- `包含人格解读、专业推荐和志愿行动建议`
- `报告生成通常需要10-30秒`

报告页要可信：

- `推荐原因`
- `适配能力`
- `需要确认`
- `下一步建议`

## 当前版本设计结论

第一版前端风格定为：`明亮赛博校园 + 抽卡报告 + 工具化报告页`。

这是最适合当前产品的平衡点：学生会觉得有趣，家长不会觉得太不靠谱，支付页也能保持可信。
